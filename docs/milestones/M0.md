# Marco M0 — Fundação

Registro do que foi entregue no primeiro marco do Zuno, com evidências reais de execução até onde foi possível verificar. Este documento não antecipa funcionalidades de M1+.

## Objetivo

Inicializar o repositório, os padrões de qualidade, a base documental e o esqueleto executável (backend + web) sem implementar funcionalidades musicais.

## Escopo entregue

### Monorepo

- Cargo workspace com o membro `server` (binário `zuno-server`, biblioteca `zuno_server`), edição 2024.
- npm workspaces: `apps/web`, `packages/api-client`, `packages/design-tokens`, `packages/shared-types`.
- Scaffold Tauri 2 em `apps/desktop/src-tauri`, excluído do workspace Rust e não compilado no M0.
- Configurações compartilhadas: `.editorconfig`, `rustfmt.toml`, `rust-toolchain.toml`, `tsconfig.base.json`, ESLint flat config, Prettier, `.gitignore`, `.env.example`.
- Scripts de verificação local: `scripts/check.sh` e `scripts/check.ps1`.

### Backend

- `GET /health` com o contrato canônico:
  - `200` `{ status: "ok", service: "zuno-server", version, uptime_seconds, database: { status: "ok" } }`;
  - `503` `{ status: "degraded", database: { status: "error" } }` quando o banco falha.
- Erros JSON `{ code, message }` com fallback `404` (`not_found`) e `500` (`internal_error`).
- Configuração tipada por env: `ZUNO_BIND_ADDR`, `ZUNO_DATABASE_URL`, `ZUNO_MUSIC_DIR`, `ZUNO_DB_MAX_CONNECTIONS`, `RUST_LOG`. Bind padrão `127.0.0.1:8080`.
- SQLite via SQLx: WAL, `foreign_keys=ON`, `busy_timeout`, pool limitado (1–32), migrations embutidas.
- Migration baseline `0001_bootstrap.sql` com `zuno_meta`.
- `tracing` estruturado, timeout HTTP de 10 s, graceful shutdown com `Ctrl+C`.
- Testes de unidade (config, parsing de URL) e de integração (health 200/503/404, migrations do zero e idempotência, PRAGMAs).

### Frontend

- `@zuno/web`: React 19 + TypeScript strict + Vite 8 + Tailwind 4, com página de conectividade que consulta `/health` via `@zuno/api-client`.
- Estados de carregamento, sucesso, degradado e erro de rede; formatação de uptime.
- `@zuno/api-client`: cliente tipado com timeout, abort e erros estáveis (`ZunoApiError`).
- `@zuno/shared-types`: contratos `HealthResponse`, `DatabaseHealth`, `ApiErrorBody`.
- `@zuno/design-tokens`: tokens CSS/JSON iniciais.
- Proxy de desenvolvimento `/health` → `127.0.0.1:8080`.

### Documentação

- `README.md`, `CONTRIBUTING.md`, `SECURITY.md`.
- ADRs 0001–0008 (incluindo Apache-2.0, Opus canônico e M1 sem auth).
- `docs/rfcs/` com processo e template de propostas (RFC ≠ ADR).
- `docs/api/openapi.yaml` (OpenAPI 3.1, apenas `/health`).
- `docs/architecture/overview.md`, `docs/architecture/audio-capabilities.md`.
- `docs/security/threat-model.md`.
- `docs/installation/development.md`.
- Este documento.

### CI e segurança

- `.github/workflows/ci.yml`: backend em Linux e Windows (fmt, clippy `-D warnings`, testes, build release no Linux) e frontend (format, typecheck, lint, test, build).
- `.github/workflows/security.yml`: `cargo audit` e `npm audit --audit-level=high` (push, PR e semanal).
- `.cargo/audit.toml` documenta a única exceção de advisory (RUSTSEC-2023-0071, `rsa` fora do grafo de build).
- Template de issue e de pull request.
- Nenhum segredo, telemetria ou serviço externo obrigatório.

### Integração ponta a ponta (backend + proxy do Vite)
Executada localmente com o backend em `127.0.0.1:18081` e o Vite em `127.0.0.1:5174`
(`ZUNO_DEV_API_TARGET=http://127.0.0.1:18081`), porque a porta 8080 desta máquina está
ocupada por software de terceiros (Steam Web Helper) — limitação de ambiente, não do projeto.


## Pendências conhecidas

- Licença **resolvida**: Apache-2.0 (25/10/2026), `LICENSE` e `NOTICE` publicados.
- Gerador automático de cliente tipado a partir do OpenAPI (ZUNO-003) ainda não implementado; o cliente atual é escrito à mão e coberto por testes.
- CI e Security executados no GitHub com sucesso; `main` protegido com os 5 checks obrigatórios.
- Nenhum teste foi executado em Raspberry Pi 3 nem em Linux local; o gate de build Linux é coberto pela matrix do GitHub Actions.
- Porta 8080 do ambiente de desenvolvimento desta máquina está ocupada por software de terceiros; o proxy do Vite é configurável via `ZUNO_DEV_API_TARGET`.
- Persistência de longo prazo, backup e recuperação pertencem a marcos futuros.
